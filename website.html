Production readiness is evidence, not a label

These six stages define the acceptance path. Their order follows task dependencies, not a promise of delivery dates. No stage is marked accepted here.

Baseline

Own the roadmap

Freeze the source and release scope. Reuse the existing dashboard candidate and keep this website visible as its own workstream.

Trust

Protect the workspace

Separate public and private data. Require authenticated, revocable access, project isolation and tested threat controls.

Delegation

Delegate within evidence and authority

Gate the exact model and role, honor leases and approvals, preserve receipts, and make independent review a first-class workflow.

Research

Trace questions to sources

Structured research briefs, permission-aware relevance search, source ledgers, reproducible reports and explicit uncertainty.

Operations

Make failure recoverable

Actionable alerts, accessible journeys, measured performance, isolated restore drills and rollback without duplicate effects.

Release

Launch only what has been proven

Reproducible artifacts, dependency and license review, accountable support, independent acceptance and a bounded human-approved launch.

Next: baseline, then one qualified task

An accountable senior must accept the programme and freeze the source/deployment baseline before promoting the next assignment. Every worker needs a verified model/runtime tier, role capability, bounded scope and valid lease. A model cannot self-promote or bypass review. Existing dashboard PR 14 and upstream tier work retain their owners.

Review packets identify why review is needed, exact files and revisions, attention areas, reviewer role and minimum tier, evidence, independence and completion criteria. A review result is not deployment permission.

Commercial and privacy boundaries

The public page never loads private project contents or holds provider credentials. Authenticated services and permission-aware search require separate backend qualification; hiding controls is not authorization.

GitHub Pages is not a free hosting platform for commercial SaaS. Keep any permitted static preview separate from the authenticated production application. Hosting selection, spending, DNS and deployment require their own approved gates.

Security verification targets a versioned OWASP ASVS matrix; accessibility targets WCAG 2.2 AA across supported journeys. These are targets, not current compliance claims. Licensing, brand review, terms/privacy, retention, support and optional payments need accountable decisions before commercial launch.
